## 2. 审计口径

一份页面规格被认为“够详细”，必须至少满足：

1. 明确说明参考图里有什么，而不是只说“照图实现”。
2. 明确页面目标、用户场景和情绪气质。
3. 明确桌面、平板、手机布局。
4. 明确组件、文案、状态、交互、数据来源。
5. 明确不能做什么，尤其不能破坏首页或编造真实数据。
6. 明确实现文件、验收方法和完成定义。
7. 有一段可直接复制给其他大模型的完整提示词。

分级标准：

| 等级 | 含义 |
|---|---|
| S3 | 可直接交给无视觉模型实施，包含视觉、结构、交互、约束、验收 |
| S2 | 可实施，但实现前需要再补局部状态或文件边界 |
| S1 | 只有概念，不足以指导复现 |
| S0 | 缺失或图文无法对应 |

## 5. 仍需实现模型特别注意的共性问题

### 5.1 不要把参考图当真实数据源

参考图用于视觉方向，不用于事实填充。以下内容只能来自真实文件或用户确认：

- 文章数量、最近更新时间、阅读分钟数。
- GitHub 仓库、star、commit、贡献图。
- 作者头像、个人简介、项目经历、教育/工作经历。
- AI 推荐理由、简历建议、学习路径。

### 5.2 不要拆散首页已经建立的气质

首页已经完成“深色系统封面 + 纸白研究内页”的叙事。后续页面要继承：

- 低饱和深绿黑。
- 暖纸白。
- 琥珀章节编号。
- 等宽命令/状态文字。
- 细线、索引、批注、脚注、手记。

不要新增：

- 大面积蓝紫渐变背景。
- 玻璃拟态后台模板。
- 过度圆角的 SaaS 卡片。
- 与首页无关的品牌色。

### 5.3 不要把工具页做成静态展示

每个工具都必须有真实可用状态：

- 空态。
- 输入态。
- 成功态。
- 错误态。
- 复制/下载/清空反馈。
- 移动端堆叠布局。

### 5.4 不要忽略 Docsify 的生命周期

Docsify 页面切换后 DOM 会重新渲染。新增 JS 必须幂等初始化：

- 避免重复绑定监听器。
- 避免路由切换后工具按钮失效。
- 避免搜索、终端、侧边栏各自抢快捷键。
