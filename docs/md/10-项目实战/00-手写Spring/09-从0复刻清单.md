## 一、先确定复刻边界

这一版不要一开始就追求完整 Spring。
先复刻核心容器，再接扩展点，最后接 AOP 和 MVC。

| 阶段 | 目标 | 对应章节 |
|---|---|---|
| 容器启动 | 配置变成 BeanDefinition | 01 |
| 对象创建 | getBean、单例池、循环依赖 | 02 |
| 属性装配 | XML ref/value、类型转换 | 03 |
| 注解能力 | 扫描、自动注入、占位符 | 04 |
| 生命周期 | Aware、init、destroy | 05 |
| 扩展机制 | PostProcessor、FactoryBean、事件 | 06 |
| 方法增强 | AOP 代理 | 07 |
| Web 入口 | MVC 请求分发 | 08 |

## 二、推荐包结构

可以先按你的 `mini-spring-iteration` 包结构走：

```text
com.wychmod.springframework
├── beans
│   ├── factory
│   │   ├── annotation
│   │   ├── config
│   │   ├── support
│   │   └── xml
│   └── PropertyValue / PropertyValues
├── context
│   ├── annotation
│   ├── event
│   └── support
├── core
│   ├── convert
│   └── io
├── aop
│   ├── aspectj
│   └── framework
└── stereotype
```

不要一开始就把所有接口补满。
每次只补当前链路要用到的类，跑通后再进入下一阶段。

## 三、第一阶段：容器启动

先写这些类：

| 类 | 作用 |
|---|---|
| `BeanDefinition` | 保存 bean 的说明书 |
| `BeanDefinitionRegistry` | 注册 BeanDefinition |
| `DefaultListableBeanFactory` | 保存定义并提供查询 |
| `BeanDefinitionReader` | 定义读取接口 |
| `XmlBeanDefinitionReader` | XML 解析 |
| `ClassPathXmlApplicationContext` | 启动入口 |

最小验收：

```java
ClassPathXmlApplicationContext context = new ClassPathXmlApplicationContext("spring.xml");
String[] names = context.getBeanDefinitionNames();
```

能看到配置里的 bean 名称，就说明第一阶段成功。

## 四、第二阶段：getBean 与单例池

再写这些类：

| 类 | 作用 |
|---|---|
| `BeanFactory` | 定义 `getBean` |
| `AbstractBeanFactory` | 先查缓存，再创建 |
| `DefaultSingletonBeanRegistry` | 三层缓存 |
| `AbstractAutowireCapableBeanFactory` | 真正创建 bean |
| `InstantiationStrategy` | 把实例化策略抽出来 |

最小验收：

```java
Object userService1 = context.getBean("userService");
Object userService2 = context.getBean("userService");
System.out.println(userService1 == userService2);
```

如果默认单例返回 `true`，说明单例池主链路通了。

## 五、第三阶段：属性填充

补这些类：

| 类 | 作用 |
|---|---|
| `PropertyValue` | 单个属性 |
| `PropertyValues` | 属性集合 |
| `BeanReference` | bean 引用 |
| `ConversionService` | 类型转换接口 |
| `DefaultConversionService` | 默认转换服务 |

最小验收：

```xml
<bean id="userDao" class="demo.UserDao"/>
<bean id="userService" class="demo.UserService">
  <property name="userDao" ref="userDao"/>
  <property name="timeout" value="1000"/>
</bean>
```

能拿到 `userService.userDao`，且 `timeout` 是目标类型，就说明 DI 主链路通了。

## 六、第四阶段：注解能力

补这些类：

| 类 | 作用 |
|---|---|
| `@Component` | 标记候选 bean |
| `@Scope` | 声明作用域 |
| `@Autowired` | 按类型注入 |
| `@Qualifier` | 按名称注入 |
| `@Value` | 注入配置值 |
| `ClassPathBeanDefinitionScanner` | 扫描并注册 |
| `AutowiredAnnotationBeanPostProcessor` | 处理字段注入 |
| `PropertyPlaceholderConfigurer` | 处理 `${...}` |

最小验收：

```xml
<component-scan base-package="demo"/>
```

```java
@Component
public class UserService {
    @Autowired
    private UserDao userDao;
}
```

能不写 `<bean>` 也拿到对象，说明注解链路通了。

## 七、第五阶段：生命周期

补这些接口和适配器：

| 类 | 作用 |
|---|---|
| `Aware` | 感知接口标记 |
| `BeanNameAware` | 感知 bean 名 |
| `BeanFactoryAware` | 感知 BeanFactory |
| `ApplicationContextAware` | 感知 ApplicationContext |
| `InitializingBean` | 初始化回调 |
| `DisposableBean` | 销毁回调 |
| `DisposableBeanAdapter` | 统一适配销毁逻辑 |

最小验收：

```java
context.registerShutdownHook();
```

关闭 JVM 前能触发 destroy，就说明销毁流程通了。

## 八、第六阶段：扩展点和事件

补这些能力：

| 类 | 作用 |
|---|---|
| `BeanFactoryPostProcessor` | 实例化前改 BeanDefinition |
| `BeanPostProcessor` | 初始化前后改 bean |
| `InstantiationAwareBeanPostProcessor` | 实例化和属性填充阶段扩展 |
| `FactoryBean` | 生产复杂对象 |
| `ApplicationEvent` | 事件基类 |
| `ApplicationListener` | 监听器 |
| `ApplicationEventMulticaster` | 事件广播器 |

最小验收：

```java
public class ContextRefreshedListener implements ApplicationListener<ContextRefreshedEvent> {
    public void onApplicationEvent(ContextRefreshedEvent event) {
        System.out.println("refreshed");
    }
}
```

容器启动后能打印事件日志，就说明事件机制通了。

补这些类：

| 类 | 作用 |
|---|---|
| `Pointcut` | 切点 |
| `MethodMatcher` | 方法匹配 |
| `Advisor` | 切点 + 通知 |

## 十一、当前实现的简化边界

| 点 | 当前实现 | 复刻时建议 |
|---|---|---|
| 预实例化 | `preInstantiateSingletons()` 直接遍历所有 `BeanDefinition` | 加 `isSingleton()` 判断，prototype 等到真正 `getBean()` 再创建 |
| 属性写入 | 主要通过字段反射写入 | 先跑通字段注入，再扩展 setter / 方法注入 |
| `@Value` 转换 | 复用占位符解析，但没有显式接入 `ConversionService` | 需要注入数字字段时，在处理器里补目标字段类型转换 |
| 初始化 | 实现 `InitializingBean` 后会跳过配置式 `init-method` | 如果对齐真实 Spring，应在方法不重复时两者都调 |
| FactoryBean | 支持实现 `FactoryBean` 的 bean 产出对象 | XML `factory-bean` / `factory-method` 可以作为后续扩展 |
| 后置处理器顺序 | 基本按注册顺序执行 | 后续可补 `Ordered` / `PriorityOrdered` |
| 自动 AOP | 自动代理创建器默认强制 CGLIB | 如需 JDK 优先，给自动代理器加配置开关 |
| MVC | 参考 `mini-spring-original` | 可以独立接入，不必和 iteration 第一轮强耦合 |

## 十二、最常见的坑

| 问题 | 原因 | 处理 |
|---|---|---|
| bean 找不到 | 没注册 BeanDefinition | 先打印 `getBeanDefinitionNames()` |
| 循环依赖栈溢出 | 没有提前暴露 | 检查 `addSingletonFactory()` 时机 |
| `@Autowired` 不生效 | 处理器没注册 | 确认扫描后注册自动装配处理器 |
| `${...}` 不替换 | 占位符处理太晚 | 放在实例化 bean 之前 |
| 初始化方法没执行 | 没接生命周期 | 检查 `initializeBean()` |
| AOP 不生效 | 自动代理器没加入后置处理器列表 | 检查 `registerBeanPostProcessors()` |
| MVC 404 | URL 正则不匹配 | 打印 HandlerMapping |

## 十三、最终完成标准

这套系列做到这里，应该能达成：

- XML 能注册 bean。
- 注解能扫描 bean。
- `getBean()` 能返回单例对象。
- `ref` 和 `value` 能完成属性注入。
- 单例循环依赖能通过早期暴露解决。
- `Aware`、init、destroy 能触发。
- 后置处理器能参与扩展。
- FactoryBean 接口能生产复杂对象。
- AOP 能包装代理对象。
- MVC 能把 HTTP 请求分发到方法。

如果这些都能跑通，你复刻的已经不是玩具版 `new Map` 容器，而是一套有 Spring 核心骨架的迷你框架。
