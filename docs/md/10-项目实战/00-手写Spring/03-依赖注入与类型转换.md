# 手写 Spring：依赖注入与类型转换

> **原文归档**：[old-spring-notes](/md/archive/README?id=old-spring-notes)
> **参考实现**：[wychmod/mini-spring](https://github.com/wychmod/mini-spring)
> **本章目标**：把 `ref`、`value` 和类型转换串起来，让 bean 真正“有关系”。

---

## 一、DI 不是把字段填满这么简单

依赖注入的核心，不是“给对象赋值”，而是“让对象之间的关系也由容器负责”。
在 Spring 里，这个关系通常有两种形态：

| 形态 | 例子 | 容器要做什么 |
|---|---|---|
| 值注入 | `timeout = 1000` | 把字符串转成目标类型 |
| 引用注入 | `userDao = userDao` | 继续去容器里找另一个 bean |

在你的实现里，这些信息都先放在 `PropertyValues` 里，再由 `applyPropertyValues()` 统一处理。

> 💡 补充：DI 的重点不是“反射”。反射只是最后那一下手段，真正重要的是先把“属性值”和“依赖关系”保存起来。

## 二、属性容器长什么样

`PropertyValue` 只保存一对键值，`PropertyValues` 负责保存一个列表。
如果这个值是另一个 bean，就用 `BeanReference` 包一层。

| 类 | 作用 |
|---|---|
| `PropertyValue` | 一个属性名 + 一个属性值 |
| `PropertyValues` | 多个属性的集合 |
| `BeanReference` | 表示这个属性指向另一个 bean |

```java
public class PropertyValue {
    private final String name;
    private final Object value;
}
```

```java
public class BeanReference {
    private final String beanName;
}
```

## 三、applyPropertyValues 的主流程

在 `AbstractAutowireCapableBeanFactory` 里，属性填充是这样走的：

1. 遍历 `BeanDefinition` 中的 `PropertyValues`。
2. 如果值是 `BeanReference`，先 `getBean()` 拿依赖对象。
3. 如果值是普通字符串，尝试做类型转换。
4. 最后通过反射写入字段。

当前系列以字段注入为主线。setter 注入、方法注入可以作为后续扩展，不要在第一轮复刻里同时展开。

```mermaid
flowchart TD
  A[PropertyValues] --> B{value 是 BeanReference?}
  B -->|是| C[getBean(依赖)]
  B -->|否| D[类型转换]
  C --> E[写入字段]
  D --> E
```

在你的 iteration 版里，这一步落在：

```java
if (value instanceof BeanReference) {
    value = getBean(beanReference.getBeanName());
} else {
    if (conversionService.canConvert(sourceType, targetType)) {
        value = conversionService.convert(value, targetType);
    }
}
BeanUtil.setFieldValue(bean, name, value);
```

这段显式接入 `ConversionService` 的路径，主要对应 XML 解析出来的 `PropertyValues`。注解 `@Value` 会在下一章通过后置处理器进入，当前实现复用的是占位符解析入口，但没有显式走这里的 `ConversionService` 分支。

## 四、value 和 ref 的差别

| 写法 | 代表什么 | 什么时候用 |
|---|---|---|
| `value="1000"` | 普通值 | 字符串、数字、布尔值 |
| `ref="userDao"` | bean 引用 | 依赖另一个对象 |

```xml
<bean id="userService" class="com.demo.UserService">
  <property name="userDao" ref="userDao"/>
  <property name="timeout" value="1000"/>
</bean>
```

这段 XML 读进来以后，不是直接创建对象，而是先形成两条信息：

- `userDao` 需要容器里的另一个 bean。
- `timeout` 是一个要转换成 `int` 的字符串。

## 五、类型转换为什么要单独做

你这里的类型转换不是为了炫技，而是为了让 XML 配置更像 Spring。

`AbstractApplicationContext.finishBeanFactoryInitialization()` 会先看看容器里有没有名为 `conversionService` 的 bean。
如果有，就把它挂到工厂上，后续属性填充时就能自动做字符串到数字等转换。

| 组件 | 作用 |
|---|---|
| `ConversionServiceFactoryBean` | 产出一个 `ConversionService` |
| `DefaultConversionService` | 提供默认转换能力 |
| `ConversionService` | 给工厂做统一类型转换 |

这意味着容器不仅能“找对象”，还能“把字符串变成对象需要的值”。

> 💡 补充：这一层一旦通了，XML `value`、XML 占位符和数字字段注入就有了统一基础。`@Value` 可以复用占位符解析思路，但当前实现没有显式走 `ConversionService`。

## 六、从 0 复刻时怎么写

最小实现可以按这个顺序来：

1. 先写 `PropertyValue` 和 `PropertyValues`。
2. 再写 `BeanReference`。
3. 再在 `applyPropertyValues()` 里处理 `ref`。
4. 再接一个简单的类型转换器。
5. 最后把反射写属性串起来。

你可以把这章理解成一句话：

> 容器不是只会创建对象，还要会把对象之间的关系和基础值一起装进去。

## 七、下一章预告

那时你会看到 XML 不再是唯一入口，`@Component`、`@Autowired`、`@Value` 也会变成容器规则的一部分。
