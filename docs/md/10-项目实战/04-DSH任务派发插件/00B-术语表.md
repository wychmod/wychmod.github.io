## 一、宿主与运行时

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **DSH**（DeepSeek Harness） | 本插件所挂载的 Agent 宿主，提供会话、模型调用、工具执行、权限审批 | 00A |
| **Host 半边** | 跑在 DSH 进程（Node）里的那部分插件代码，即 `src/` 下 14 个模块 | 00 |
| **Client 半边** | 跑在浏览器页面里的那部分，即 `client/index.js` 单文件 12,586 行 | 00 |
| **bundle** | 插件发布形态：一个含 `package.json` 的目录，入口是 `apply(ctx, config)` | 00A |
| **`ctx`** | cordis 的作用域上下文。注册在根 `ctx` 上 = 全局层；注册在 `agent.ctx` 上 = 只对该会话可见 | 00A |
| **槽位（slot）** | 宿主界面预留的可插入点，如 `conversation.input.left`、`tool.call.toolview`、`conversation.chat.node` | 02 |
| **`inject`** | 插件声明依赖的宿主服务列表；本插件硬依赖 4 个：`tools` / `agents` / `sessionController` / `connection` | 00 |

## 二、派发链路

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **主会话** | 发起派发的那个 Session。它写简报、派活，然后结束本轮 | 00 |
| **worker / 子会话** | 被派出去干活的那个 Session。**它是真会话，有历史，能追问**，不是一次性执行器 | 01 |
| **brief（简报）** | 投给 worker 的自包含任务描述。四段：目标 / 约束 / 验收 / 已知事实。**worker 看不到主会话历史** | 00A |
| **派发即移交** | 返回之后，该任务的任何执行环节（读代码、跑脚本、开浏览器）都不再由主会话进行 | 06 |
| **relay（回流）** | 把 worker 的报告作为一条**插件来源**的消息投回主会话。来源标记是 `{kind:'dsh-mini-superagent', form:'relay'}` | 01 |
| **`followup` / `steer`** | 两种投递方式：主会话空闲用 `followup`（唤醒），忙碌用 `steer`（并入下一步） | 01 |
| **四段式报告** | worker 汇报的固定格式：`【任务】【结果】【说明】【需要你】【细节】【批次】` | 11 |
| **`headline`** | 报告里「一句话给用户看的结论」。`summary` 是技术摘要，用户不一定读 | 16 |

## 三、队列与状态

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **`pump()`** | 队列推进器：占并发位、取可运行任务、启动子会话。**必须挂在每个结算点上**，否则空出的并发位没人用 | 01 |
| **并发位** | 同时 `running` 的上限，由 `maxWorkers` 控制（默认 6）。**是软上限** | 00A |
| **`queued`** | 已派出去、在等并发位。**不是「没派成」**——这是本项目最常见的误读 | 00A |
| **`SETTLED`** | 六个已结算状态的集合：`done` / `blocked` / `failed` / `cancelled` / `ended` / `interrupted`。不再占并发位 | 01 |
| **`TRANSITIONS`** | 状态跃迁表。任何状态变更都必须走 `transition()` 这一个写入口 | 05 |
| **`reopen()`** | 唯一能把终态任务拉回 `running` 的显式入口（`dispatch_message` 内部用它） | 05 |
| **`blockedBy`** | 派生字段，语义是「此刻第一个没满足的前置」。由 `pump()` 每轮重算，**不是持久事实** | 09 |
| **`group`** | 批次 id。同一次 `launch_many` 派出的任务共享它，看板据此聚合 | 11 |

## 四、权威源与投影

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **账本（ledger）** | `tasks.json`，派发事实的**唯一权威**。任务归属、报告正文、投递成败、`attempt` 全在这里 | 07 |
| **投影（projection）** | 从账本读出来渲染的那一份（会话里的报告消息、看板快照、卡片）。**可以更短、可以丢、可以重放，但不得反过来成为事实** | 07 |
| **准入分级** | 哪些状态的报告能叫醒主会话。终态**恒直通**，配置只能扩展不能降级 | 07 |
| **合并窗口** | 同一任务窗口内的多条 `progress` 只发最后一条。**只有过程态可合并**，结论类永不参与 | 07 |
| **归档（archive）** | 会话从侧边栏收起，**历史还在**，报告正文可查。不改变任务状态 | 03 |
| **退休（retire）** | 任务移出活表，只留 18 字段薄记录 + 200 字摘要。**不可撤销** | 07 |
| **版本闸门** | 读 `tasks.json` 时校验 `version`。过新/过旧都 fail-closed，原文件一字不改 | 07 |

## 五、约束与降级

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **结构性约束** | 模型**不该有能力**做的事，用工具面实现（`tools.restrict({deny})`）。例：必派发会话不许改代码 | 06 |
| **语义约束** | 模型该自己判断的事，用提示词实现（穷举正反例 + 量级）。例：派完该结束本轮 | 06 |
| **路由模式** | 把派发目标设成具体工作区或「自动」时，收走 `write` / `edit`，模型只能派活。**`bash` 默认保留** | 06 |
| **降级矩阵** | 「失败点 → 怎么检测 → 降级成什么 → **明确禁止什么**」。最后一栏是多数人会漏的 | 11 |
| **L0–L3** | 四档降级：全功能 / 数据降级 / 单卡拉闸 / 双卡拉闸。**两张卡各自独立** | 11 |
| **fail-closed** | 拿不到权威依据时**拒绝**，而不是放行。0.10.4 起看板在问不到 `connection` 时回 503 | 12 |

## 六、工作区与连续性

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **会话归属** | 子会话挂在哪个工作区下，决定侧边栏分组。**建完不可迁移** | 03 |
| **工作目录（cwd）** | 子会话实际读写的位置。**每个任务可以不同** | 03 |
| **派发目标** | 输入框控件设的「下一次从我这个会话派出去的任务去哪个工作区」。**不搬会话** | 04 |
| **`workerWorkspace`** | 只决定**无目标时**的兜底（`day` = 当天【派发】/ `cwd` = 任务目录） | 03 |
| **`depends_on`** | 前置任务列表。**全满足语义**：`['A','B']` = A 且 B 都 done 才启动 | 09 |
| **`handoff_from`** | 新建任务，**沿用来源子会话**的上下文。与续派（`continue_task_id`）不同，它会新建任务 | 09 |
| **`continue_task_id`** | 在**同一个任务**上补一句要求，不新建任务。转发成一次 `dispatch_message` | 09 |

## 七、诊断

| 术语 | 一句话定义 | 首见 |
|---|---|---|
| **`selfcheck`** | `GET /board/selfcheck`，回答「为什么没生效」。核心是 `client.inGraph` / `client.ready` / `client.probes` | 02 |
| **`inGraph` vs `ready`** | 前者是「模块进了启动图」，后者是「它在页面里真的跑起来了」。**两件事** | 02 |
| **`probes`** | 对已知正常的其它包做同样探测。全空说明**探测方法本身不可靠**，不是本插件坏了 | 02 |
| **负向验收** | 还原修复后测试必须变红，用来证明「测试真的在测那件事」 | 12 |
| **`LOG_PREFIX`** | 日志统一前缀 `dsh-mini-superagent:`。排障时先 grep 它 | 15 |
