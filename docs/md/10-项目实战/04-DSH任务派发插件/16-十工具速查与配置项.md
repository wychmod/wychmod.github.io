## 一、工具全景：10 个，分三类

| # | 工具 | 谁调 | 一句话 |
|---|---|---|---|
| 1 | `dispatch_launch` | 主会话 | 派一条任务，立即返回 |
| 2 | `dispatch_launch_many` | 主会话 | 一次派 1–16 条（可声明依赖） |
| 3 | `dispatch_workspaces` | 主会话 | 列出可用工作区 |
| 4 | `dispatch_candidates` | 主会话 | 列出「可接续的候选」，只给素材不给推荐 |
| 5 | `dispatch_list` | 主会话 | 列本会话派出的任务 |
| 6 | `dispatch_inspect` | 主会话 | 看一条任务的全貌 |
| 7 | `dispatch_message` | 主会话 | 给子会话追加一条消息 |
| 8 | `dispatch_cancel` | 主会话 | 取消一条任务 |
| 9 | `dispatch_wait` | 主会话 | 阻塞等待（**默认不要用**） |
| 10 | `dispatch_report` | **worker** | 向派发你的主会话汇报 |

**10 个工具全部注册在全局层**，所以 worker 也能看见前 9 个。角色靠运行时判定：`dispatch_report` 只允许 worker 调，其余只允许主会话调。

**这个集合是长出来的**，不是一次设计好的：

```text
0.1.0  8 个（launch / launch_many / list / inspect / message / cancel / wait / report）
0.4.0  +dispatch_workspaces
0.9.0  +dispatch_candidates
```

**名字从 0.2.0 就冻结了**，之后只加不改。

## 二、派发类

### `dispatch_launch`

**必填**：`title`、`brief`。其余 11 个全可选。

| 参数 | 类型 | 说明 |
|---|---|---|
| `title` | string | 任务短标题（≤120 字），用于列表与子会话标题 |
| `brief` | string | 完整简报。**子会话看不到本会话历史，必须自包含** |
| `cwd` | string | 子会话工作目录绝对路径。**优先级高于输入框记住的派发目标** |
| `workspace` | string | 工作区 id / 绝对路径 / 标题。**同名不会猜**，报错并列出候选路径 |
| `create_workspace` | bool | 默认 `true`。解析不到时是否新建。**名字有歧义时不论开关都不新建** |
| `model` | string | `model` 或 `provider/model`。宿主不支持切换时**这次派发失败并说明原因**，不静默改用默认 |
| `agent_preset` | string | 子会话的 agent preset id |
| `permission_preset` | string | 权限预设（如 `danger-full-access`） |
| `continue_task_id` | string | 续派：同一个任务追加要求，**不新建任务** |
| `handoff_from` | string | 复用：**新建任务**但沿用来源会话 |
| `no_reuse` | bool | `true` = 强制新开。优先级 `no_reuse` > `handoff_from` > 都不传 |
| `handoff_reason` | string | 为什么接上一轮。≤200 字，**只写账本，不参与任何判定或打分** |
| `depends_on` | array | 前置任务 id，≤8 个。去重去空、必须存在、不能指向自己 |

**返回**：

```json
{
  "task": { ...card 形状... },
  "depends_on": [],
  "note": "已入队/启动；接下来默认结束本轮，不要在本轮等它完成，报告会自己回来。"
}
```

三个条件字段只在特定情形出现：`continued: true`（续派）、`handoff: true` + `reused_session`（复用成功）、`reuse_degraded: true`（复用降级，原因在 `note` 里）、`forced_new_session: true`（`no_reuse` 生效）。

**互斥约束**：`continue_task_id` 与 `handoff_from` **同时传会报错**，不按优先级猜。`continue_task_id` 也不能同时传 `depends_on`（续派不新建任务，依赖无处安放）。

### `dispatch_launch_many`

**必填**：`tasks`（数组，1–16 项）。每项必填 `title` / `brief`，可选参数与 `dispatch_launch` 大部分相同，但多一个 `depends_on_index`。

| 参数 | 说明 |
|---|---|
| `depends_on_index` | 批内下标（0 起），**只能指向本批中排在自己前面的 item**。服务端在第 i 项成功后替换成真实 id。与 `depends_on` 同时给时合并去重 |

**返回**：

```json
{
  "group": "g-xxxxxx",
  "launched": [
    {"task_id":"t-...-1","title":"改接口","status":"queued","depends_on":[]},
    {"title":"补实现","error":"...","code":"dispatch/unknown-dependency"}
  ],
  "note": "全部结算后会收到一条批次汇总。"
}
```

**关键细节**：失败项**占住数组位置**（`launchedIds.push(undefined)`）。所以后面的 item 用 `depends_on_index` 指向它时会解析失败报 `UNKNOWN_DEPENDENCY`——而不是**错位指向别人**。

## 三、观察类

### `dispatch_workspaces`

**无参数**。返回工作区列表：

```json
[{"workspace_id":"...","title":"...","path":"...","sessions":3}]
```

派发时用 id 或标题都行。**任务明显属于新项目、列表里没有合适工作区时**，可以直接用绝对路径派发（会自动登记，越界会记 warn）。

### `dispatch_candidates`

| 参数 | 默认 | 说明 |
|---|---|---|
| `limit` | 5 | 返回条数上限 |
| `days` | 7 | 只看最近 N 天**结算**的任务 |
| `cwd` | 会话当前目录 | 按目录圈定「同域」 |
| `workspace` | —— | 按工作区圈定；与 `cwd` 同时给时**两个都要满足** |
| `all_workspaces` | false | `true` 时不按同域过滤，只用于「跨目录看一眼」。**跨目录的候选不能当复用来源** |

**红线**：返回里**没有** `score` / `rank` / `recommend` / `confidence` / `match` / `similarity` 任何打分或推荐字段，由 `test/handoff-candidates.test.js` 把守。「这两条是不是同一件事」是语义判断，只能由调用方的模型做。

**`excluded` 字段**：把「为什么没候选」也返回（`not_settled` / `cancelled` / `archived` / `retired` / `outside_window` / `other_domain`）。没有它，用户看到空列表只能猜。

### `dispatch_list`

| 参数 | 默认 | 说明 |
|---|---|---|
| `all` | `true` | `false` 只看未结算的 |
| `limit` | 20 | 返回条数上限 |

**返回**：

```json
{"version":"0.10.4","total":7,"running":2,"max_workers":6,"tasks":[...]}
```

`total` 是**本会话**的任务数（不是全局）。看板是全实例的，两者数量不同**不是 bug**。

**`tasks[]` 的每项是 `card()` 的形状**。注意 `card()` **刻意不含 `plan`**——它同时服务 `list` 与 `inspect`，把步骤数组塞进列表会让返回体膨胀数倍。计划只在 `dispatch_inspect` 的 `detail()` 里给。

### `dispatch_inspect`

**必填**：`task_id`。

比 `card()` 多出的字段：`blocked_reason`、`cancel_reason`、`error_code`、`plan`（全量步骤）、`recent_reports`、`last_worker_text`。

**已退休的任务仍可查**：返回 `retired: true` 与退休时刻/原因，但**没有报告正文**（退休只留 18 字段薄记录 + 200 字摘要）。

## 四、干预类

### `dispatch_message`

**必填**：`task_id`、`message`。

| 参数 | 默认 | 说明 |
|---|---|---|
| `mode` | `queue` | `queue` 排到下一轮（空闲时唤醒）；`steer` 并入当前回合的下一步 |

投递后任务重新变为 `running`。**任务还在等前置（`depends_on` 没满足、停在 `queued`）时直接报错** `dispatch/conflict`——此时投递会把它变成 `running`，打乱声明好的先后顺序。

### `dispatch_cancel`

**必填**：`task_id`。可选 `reason`（记录在任务上）。

取消会结束子会话当前回合并释放并发位。**已产生的工作不会回滚**——需要时自己检查工作目录。

### `dispatch_wait`

| 参数 | 默认 | 说明 |
|---|---|---|
| `task_ids` | 本会话全部未结算 | 省略即等全部 |
| `timeout_ms` | 60000 | 超时毫秒 |

**默认不要调用它。** 唯一允许的情形：用户在**同一条消息里**明确要求「等结果再继续」，且不拿到结果就无法产出他要的东西。

**它不是 sleep**：超时后任务可能仍在 `running`，再等一次只是再阻塞一次。等一个被前置挡住的排队任务时，它会一直等到该任务被启动并结算、或被连带取消。

**返回**（0.9.1 起）：`{timed_out, unsettled, tasks}`。旧版只有 `waited` 与 `tasks`，而 `status` 在「等到了」和「等满了」两种情形下都可能是 `running`——无法区分。

## 五、worker 侧唯一的一个

### `dispatch_report`

**必填**：`status`、`summary`。

| 参数 | 说明 |
|---|---|
| `status` | `done` / `blocked` / `failed` / `progress` |
| `headline` | 可选但**强烈建议**：一句话给用户看的结论，≤40 字。不含任务 id、不含英文状态词、不重复任务名 |
| `summary` | 3–6 行技术摘要：做了什么、结果如何、需要主会话做什么 |
| `detail` | 可选长详情：改动清单、验证命令与输出、遗留问题。**只进账本与 `inspect`，不随报告回流** |
| `plan` | 可选：数组顺序即执行顺序；**每次传都是整版替换**，最多 12 步 × 120 字，超出截断并返回 `plan_truncated` |

**`plan_accepted` 的语义陷阱**：这个字段表示「本条报告有没有一版计划被接受」。**没传 `plan` 时它也是 `false`**——不是「计划被拒绝」。这个歧义必须在文档里写清，否则调用方会误判。

**主会话不要调用这个工具。**

## 六、47 个配置项分组清单

全部可选，写在 `cordis.patch.yml` 的 `config` 段。整段删掉也能工作。

### 并发与额度（3）

| 键 | 默认 | 说明 |
|---|---|---|
| `maxWorkers` | `6` | 同时 `running` 的上限。**软上限** |
| `maxTasksPerSession` | `64` | 每个主会话的额度。**只数仍在册的**，不是终身累计 |
| `allowSessionReuse` | `true` | 关闭后复用降级，返回值一定带 `note` |

### 工作区与目录（8）

| 键 | 默认 | 说明 |
|---|---|---|
| `workspaceRoot` | `''` | 工作区根。空 = `<用户文档>/mini-superagent` |
| `provisionDefaultWorkspace` | `true` | 启动时确保默认工作区与 `mas-lead` 主会话存在（幂等，失败只记日志） |
| `leadSessionId` | `'mas-lead'` | 默认主会话 id |
| `workerWorkspace` | `'day'` | 无目标时的兜底：`day` 当天【派发】/ `cwd` 任务目录。**管不到有目标的派发** |
| `inheritWorkingDirectory` | `true` | 子会话是否继承主会话工作目录 |
| `taskDirRoot` | `''` | 每任务目录的根。空 = 不启用 |
| `prepareCommand` | `''` | 每任务目录的 prepare 命令（典型用法 `git worktree add`） |
| `prepareTimeoutMs` | `600000` | prepare 超时（10 分钟）。超时即失败，**不自动重试** |

### 归档与退休（5）

| 键 | 默认 | 说明 |
|---|---|---|
| `archiveAfterHours` | `168` | 结算后多少小时自动归档（7 天）。24 会让看板「全部」隔一天就空 |
| `archiveSweepMinutes` | `10` | 归档巡检间隔。首次延迟 20 秒 |
| `ledgerMaxTasks` | `1000` | 账本条数上限，超出按「已归档优先 → 最老 updatedAt」退休 |
| `ledgerMaxDays` | `90` | 非活跃且超过 N 天的任务退休 |
| `ledgerMaxRetired` | `5000` | 退休留痕条数上限，超出丢最老的并 `retiredDropped += 1` |

### 报告与体积（9）

| 键 | 默认 | 说明 |
|---|---|---|
| `maxBriefChars` | `12000` | 简报落盘上限，超出截断 |
| `maxReportSummaryChars` | `6000` | 报告 summary 入库上限 |
| `maxReportDetailChars` | `4000` | 报告 detail 入库上限 |
| `maxLastTextChars` | `5000` | worker 最后一段输出上限 |
| `maxPlanSteps` | `12` | 计划步数上限，超出**截断不报错** |
| `maxPlanStepChars` | `120` | 单步文案上限 |
| `maxDependsOn` | `8` | 单任务前置数上限，超出**报错不静默截断** |
| `reportOnTurnEnd` | `true` | worker 回合结束后自动回报最后输出 |
| `memoryWindowDays` | `7` | 效果指标窗口（天） |
| `memoryWindowTasks` | `200` | 效果指标窗口（条） |

### 投递与合并（4）

| 键 | 默认 | 说明 |
|---|---|---|
| `progressRelayIntervalMs` | `60000` | `progress` 最短回流间隔。0 = 不节流。被挡下的仍入库 |
| `noticeMergeWindowMs` | `1500` | 合并窗口。**只有 `progress` 可合并**，上限 2000 |
| `relayRetryMs` | `[2000,4000,8000]` | 报告投递失败的重试退避序列 |
| `directReportStatuses` | `['blocked','failed']` | 额外直通的状态。**终态恒直通，配置只能扩展不能降级** |

### 路由与权限（4）

| 键 | 默认 | 说明 |
|---|---|---|
| `restrictRouter` | `true` | 是否启用路由模式的工具收窄 |
| `routerDenyTools` | `['write','edit']` | 收窄的工具名。**`bash` 默认保留**，要硬边界就加进来 |
| `permissionPreset` | `''` | 子会话权限预设。空 = 继承 DSH 默认 |
| `workerAgentPreset` | `''` | 子会话 agent preset。空 = 部署默认 |

### 容错与后台活（4）

| 键 | 默认 | 说明 |
|---|---|---|
| `retryTransient` | `true` | 瞬时故障（HTTP 408/429/5xx、连接重置）自动续跑 |
| `retryBackoffMs` | `[15000,30000,60000]` | 续跑退避序列，长度即最大重试次数 |
| `backgroundPollMs` | `15000` | 后台 shell job / subagent 的巡检间隔 |
| `backgroundLimitMs` | `1800000` | 后台活最多再占 30 分钟，到点终止再结算。0 = 不限（不建议） |

### 接续与诊断（5）

| 键 | 默认 | 说明 |
|---|---|---|
| `autoHandoff` | `false` | **只控制提示注入**，不是自动绑定。默认关：它改变模型行为 |
| `handoffCandidatesDays` | `7` | 候选窗口天数 |
| `handoffCandidatesLimit` | `5` | 候选条数上限 |
| `handoffBriefChars` | `600` | 候选里简报的截断长度 |
| `handoffReportSummaryChars` | `600` | 候选里报告摘要的截断长度 |
| `inputPendingTtlMs` | `1800000` | 输入框待处理项的存活时间（30 分钟） |
| `clearTargetsOnDispose` | `true` | 会话销毁时清掉它的派发目标 |
| `allowBoardWithoutConnectionGate` | `false` | **逃生阀，不建议开**。只放开「问不到 `connection`」这一档，401/403 仍会拒 |
| `stateDir` | `''` | 账本目录。空 = `$DSH_HOME/dsh-mini-superagent` |

> 上面按用途分了 8 组，实际键数是 47。分组是本文的组织方式，不是代码里的结构——`DEFAULTS` 是一个平铺对象。

## 七、六个最容易用错的参数

| # | 参数 | 错法 | 后果 |
|---|---|---|---|
| 1 | `brief` | 写「修一下那个 bug」 | worker 从零猜，报告里全是假设。成本转移到「看完发现全错、重派一次」 |
| 2 | `workspace` | 写一个同名工作区的标题 | **不会猜**，报错并列出候选路径。改用 id 或绝对路径 |
| 3 | `continue_task_id` + `handoff_from` | 一起传 | **直接报错**，不按优先级猜。前者是同任务追加，后者是新建任务 |
| 4 | `depends_on_index` | 指向自己或后面的项 | 报错。只能指向**本批中排在自己前面**的 item |
| 5 | `directReportStatuses` | 想「清空它来关掉 `done` 回流」 | 做不到。`admissionOf()` 对终态恒 `direct` |
| 6 | `routerDenyTools` | 以为配了 `['write','edit']` 就写不了文件 | **`bash` 仍在**，`echo > file` 照样能写。要硬边界要把 `bash`/`pwsh` 一起加进去 |
