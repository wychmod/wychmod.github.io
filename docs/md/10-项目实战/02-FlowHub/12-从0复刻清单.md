## 二、阶段 0：环境与工程脚手架

前置依赖：JDK 21、Node.js ≥ 18、MySQL 8.0+（本机 3306，需 `flowhub` 库与 `flowhub/flowhub` 账号）；RabbitMQ 与 Redis **可选**——未启动时分别自动补发/降级。

```bash
# 后端脚手架（Maven Wrapper 免装 Maven）
spring init  # 或手写 pom：web / validation / mybatis / flyway / amqp / data-redis / poi-ooxml / actuator

# 前端脚手架
npm create vite@latest frontend -- --template react-ts
npm i antd @tanstack/react-query dayjs

# 中间件（可选）
docker compose up -d rabbitmq redis   # 管理台 http://localhost:15672（guest/guest）
```

配置约定：后端 8080、前端 5174；统一响应 Envelope、API v1 集中前缀；`logback-spring.xml` 控制台 Appender 包 `AsyncAppender(neverBlock=true)`（防 Windows 快速编辑模式冻结接口，见[第 01 章](01-公共底座.md)坑四）。

最小验收：后端日志出现 `Started FlowHubApplication`，前端页面可访问。

## 三、阶段 1：表结构（Flyway V1~V9）

按演进顺序建迁移脚本，每一步都可追溯：

| 版本 | 内容 | 服务于 |
|---|---|---|
| V1 | `orders` / `export_jobs` / `export_job_attempts` / `outbox_events` 四张核心表 | 全链路地基 |
| V2 | `export_jobs` 加 `idempotency_key`（唯一约束）/ `request_hash` / `filter_count` | 幂等创建 |
| V3 | `export_jobs` 加请求快照 4 列（`filter_snapshot` / `selected_order_ids` / `selected_columns` / 文件名） | 执行时可重放 |
| V4 | 执行状态字段（`processed_rows` / `attempt_count` / `started_at` / `finished_at` / `expired_at` / 文件字段等） | 进度与产物登记 |
| V5 | 租约字段（`last_heartbeat_at` / `lease_expires_at`）+ RUNNING 租约索引 | 崩溃恢复 |
| V6 | `orders` 补全 9 列导出业务列（`order_status` / `sales_channel` / `currency` 等）并回填 | 导出列定义 |
| V7 | `outbox_events` 加 `trace_id` 列 + 索引 | 异步链路追踪 |
| V8 | 订单查询索引（等值在前、范围/排序在后；低基数列不单独建索引） | 列表查询性能 |
| V9 | `import_jobs` / `import_job_attempts` 两张导入表（含 `succeeded_rows` / `skipped_rows` / 错误报告路径） | 导入链路 |

V1 核心表速览：

```sql
CREATE TABLE orders (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    order_no      VARCHAR(64)   NOT NULL,       -- 业务唯一键
    customer_name VARCHAR(128)  NOT NULL,
    status        VARCHAR(32)   NOT NULL,
    total_amount  DECIMAL(18,2) NOT NULL,
    created_at    TIMESTAMP     NOT NULL,
    CONSTRAINT uk_orders_order_no UNIQUE (order_no)
);

CREATE TABLE export_jobs (
    id                     BIGINT AUTO_INCREMENT PRIMARY KEY,
    job_no                 VARCHAR(64) NOT NULL,
    status                 VARCHAR(32) NOT NULL,  -- PENDING/RUNNING/SUCCEEDED/FAILED/EXPIRED
    max_order_id_at_create BIGINT      NOT NULL,  -- 高水位快照
    version                BIGINT      NOT NULL DEFAULT 0,
    created_at             TIMESTAMP   NOT NULL,
    updated_at             TIMESTAMP   NOT NULL,
    CONSTRAINT uk_export_jobs_job_no UNIQUE (job_no)
);

CREATE TABLE export_job_attempts (              -- 每次尝试一行，审计可追溯
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    job_id BIGINT NOT NULL, attempt_no INT NOT NULL,
    status VARCHAR(32) NOT NULL,
    started_at TIMESTAMP, finished_at TIMESTAMP, created_at TIMESTAMP NOT NULL
);
CREATE UNIQUE INDEX uk_attempt_job_no ON export_job_attempts (job_id, attempt_no);

CREATE TABLE outbox_events (                    -- 事务性 Outbox：先记账再发货
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    aggregate_type VARCHAR(64) NOT NULL, aggregate_id BIGINT NOT NULL,
    event_type VARCHAR(64) NOT NULL, payload LONGTEXT NOT NULL,
    published_at TIMESTAMP, created_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_outbox_unpublished ON outbox_events (published_at, created_at);
```

最小验收：启动应用 Flyway 全部执行成功；灌入演示数据（`backend/scripts/seed-demo-data.sh`，默认 20 万行，仅表为空时写入）。

## 四、阶段 2~3：公共底座与订单查询

先写底座再写业务（为什么与怎么做见[第 01 章](01-公共底座.md)）：

| 类 | 作用 |
|---|---|
| `ApiResponse` + `ApiResponseAdvice` | 统一 Envelope 自动包装 |
| `GlobalExceptionHandler` + `ErrorCode` | 全局异常唯一出口 |
| `TraceIdFilter` + `MdcTaskDecorator` | trace_id 贯穿同步与异步 |
| `ParamUtils` | trimToNull / 多值拆分 / 枚举解析 / escapeLike |

再写订单查询（[第 02 章](02-订单查询模块.md)）：record + `@BindParam` 收参 → Service 归一化校验 → `OrderQuery` 值对象 → `criteriaConditions` 共享片段动态 SQL。

最小验收：`GET /api/v1/orders` 八项筛选可组合，非法枚举 400，排序回显生效值；行为对齐测试通过。

## 五、阶段 4~6：导出异步主干（项目核心）

按「受理 → 投递 → 执行 → 发布」的顺序搭：

1. **受理与幂等**（[第 03 章](03-导出任务创建与幂等.md)）：`CreateExportJobCommand` 规范化 + SHA-256 request hash + 同事务双写 `export_jobs(PENDING)` 与 `outbox_events`；
2. **可靠投递**（[第 04 章](04-可靠投递-Outbox与消费.md)）：`OutboxDispatcher` 每 5s 扫未发布事件 → Publisher Confirm 后单向回填 `published_at`；消费者手动 Ack 四象限 + CAS 条件抢占（同事务建 Attempt）；
3. **执行与发布**（[第 05 章](05-导出执行与Excel生成.md)）：执行壳统一收敛失败 → Keyset 游标批查（`id > lastId AND id <= 高水位`）→ `SXSSFWorkbook(100)` 流式写 + `safeText` 防注入 → `ATOMIC_MOVE` 原子发布 → `markSucceeded` 登记（失败补偿删除）。

最小验收：创建任务返回 202；MQ 未启动时事件留在 outbox（`outbox_publish_deferred` 日志）；启动 RabbitMQ 后任务自动流转到 SUCCEEDED 并能下载。

## 六、阶段 7~9：进度、文件与恢复

- **进度与 SSE**（[第 06 章](06-进度状态与SSE实时通知.md)）：条件 UPDATE 三道闸（终态单向 / 单调递增 / 顺路续租），0 行影响 fail-fast；Redis 投影尽力写入；`@TransactionalEventListener(AFTER_COMMIT)` 广播，事件 id = `jobId:version`；
- **文件安全**（[第 07 章](07-文件安全与下载.md)）：`exportRoot` 启动期提纯 + `RootedPathGuard` 双层防腐（normalize 拒 `..` + 逐段符号链接验真）；下载只认 DB 登记路径，丢失报 `EXPORT_FILE_MISSING` 不重生成；
- **恢复与清理**（[第 08 章](08-恢复与清理.md)）：启动恢复只收敛租约失效的 RUNNING；每小时过期清理（删除成功才 EXPIRED）+ 孤儿三维对账（宽限期 / 无活跃租约 / 无 DB 引用）。

最小验收：SSE 能看到进度推送且乱序无害；手工 kill -9 后重启，僵尸任务被收敛为 FAILED 可人工重试；`export-files/` 无永久孤儿。

## 七、阶段 10：导入链路

对称复刻导出管道（独立表、独立 `import.job.*` 拓扑），叠加导入特有件（[第 09 章](09-订单Excel导入.md)）：

- 文件级 / 结构级同步 400（PK 魔数 + SAX 轻扫表头），行级异步；
- SAX 逐行读 + 四层防重（文件内 HashSet → DB 预查 → 唯一约束 → DuplicateKey 逐行降级）；
- PARTIAL 终态 + 错误报告 xlsx（行号对齐 Excel）+ 9 列模板内置下拉。

最小验收：上传混错文件得到 PARTIAL，错误报告行号与原文件对齐；重复上传自动跳过已有订单。

## 八、阶段 11~12：前端与测试

前端（[第 10 章](10-前端交互层.md)）：先搭 `api/` 防腐层（`requestJson` / `download.ts` 双面响应），再写订单页（草稿与已提交分离、零位移表格）、导出/导入任务页、`useExportEvents` 状态机（版本栅栏 + 轮询降级）。

测试（[第 11 章](11-测试与质量守门.md)）：

```bash
cd backend && .\mvnw.cmd test      # H2 内存库，不依赖外部中间件
cd frontend && npm test && npm run build
cd frontend && npx playwright test  # 需前后端已运行
```

最小验收：幂等并发 / 抢占零副作用 / 回滚不广播 / 路径防腐 / 活跃租约不误伤全部有专项用例；Playwright 全链路绿灯且零 console error。

# 双击 start.bat（Windows）：自动装依赖，分窗启动后端 8080 与前端 5174
