## 一、视觉方向：纸白为底，墨黑为骨

空气扑克采用「白纸黑墨动态漫画」方向：以纸白为底，让分镜、线条、网点与灰阶水光承载气氛，把清晰的牌面、数字和操作留在前景。

| 视觉要素 | 用法 |
|---|---|
| 底色 | 纸白（#f2f0e9 一带），首页过场在 V2.1 后也转为纸白 |
| 骨架 | 墨黑线稿（#151515 一带），保留留白与网点 |
| 风险色 | 少量暗红（如 #8d2429），用于失败、灾厄、危险提示 |
| 水下感 | 灰阶明暗与上升气泡，呼应「空气 / 水下圆桌」主题 |
| 字体尺度 | 宣传片里正文 42–68 px、主标题 100–180 px（同一套视觉语言） |

视觉演进有清晰的时间线：V2（2026-10-24）落地八页动态漫画界面；V2.1 同日做「白纸黑墨」修订，首页与过场转纸白底、统一灰阶边线；V3（2026-10-30）追加电影感收尾动效层。每一版都有独立的实施记录与验收证据。

## 二、八页界面全景

| 页面 | 内容 | 记忆点 |
|---|---|---|
| P01 首页 | 深墨双人圆桌、人物轻浮、慢水光气泡、单一开始入口、真实最近完成局 | 一个入口，不分散注意力 |
| P02 介绍规则 | 三个代码绘制图示，可单独播放/重播；六章导航浮层 | 图示实时绘制，非预生成 |
| P03 教学 | 选数字/锁牌、支付、失败与弃牌与灾厄、供气与宽限四项练习，可重练 | 独立练习，不动正式对局 |
| P04 对战 | 单一中央牌桌、精简资源栏、候选完整显示 | 手机候选纵向排列 |
| P05 胜利 | 抬手墨弧；V3 加中心辉光、墨色扩散、横扫光束、上升微粒 | 情绪向上的收尾 |
| P06 失败 | 面罩近景；V3 加压暗边缘、红色裂线、下坠尘埃 | 局部密网点 + 少量暗红 |
| P07 平局 | 对称浅纸水平水纹 | 克制的对称构图 |
| P08 复盘 | 全屏档案浮层、回合/尝试导航、完整牌面、逐笔事件、可播放定位、五账户趋势、JSON 导出 | 事实的完整呈现 |

八页在 320px–1440px 之间自适应，手机、平板、桌面共用同一套状态与规则。

## 三、真实渲染，不用假图冒充

这是界面最值得称道的一条原则：**所有卡牌、数字、按钮、墨弧、气泡、资金路径都由 HTML / CSS / JS / SVG / Canvas 实时呈现，不预生成视频帧，也不使用带示例数据的整页图片冒充可操作界面。**

界面上的每个数字、每张牌、每笔账目都由真实对局状态渲染。你在截图里看到的牌面，就是引擎里那副牌——不是美术画上去的示意。这让「界面即状态」成立：界面永远说真话，因为它没有能力说假话。

教学页是个例外但方向一致：它持有独立的练习视图状态，复用 `hand-builder` 与 `battle` 的纯编辑器模板，**不 dispatch 正式动作**。所以教学再怎么点，也不会污染正式对局。

## 四、动效如何由事实驱动

表现层的核心逻辑在 `browser/scene-motion.js`：它无运行模块依赖，从**前后公开快照**识别哪些动作已被接受，并用真实的 `betting.history.paid` 区分「支付」与「呼吸开罐」。

| 动效 | 触发依据 | 约束 |
|---|---|---|
| 出牌、支付、翻牌、灾厄反馈 | 公开事件快照 | 只消费事件，不派发动作 |
| Canvas 场景动效 | 已接受动作 | 像素倍率上限 2；隐藏页面停止绘制 |
| 终局收尾（约 2.9 秒） | 进入 summary 的事实 | 不拦截指针，结束自动移除 |
| 转场墨幕 | 页面切换 | 全屏左向右擦除，首屏不播 |
| 区块浮入 | 渲染 | 150 ms 起始、45 ms 步进 |
| 倒计时刻度环 | 真实剩余时间 | 10 秒内转红脉冲，数值上滚 |

所有动效只用 `transform` / `opacity` / `filter` 实现，性能好、可控性强。恢复页面时**不补播过时事件**——动画不是待办队列，不会因为你离开一会儿就积压一堆要补演的镜头。

## 五、V2 到 V3 的演进

**V2.0（八页实施）** 的验收：48 个 JS 文件语法、22 个浏览器模块、90 项测试 0 失败、31 项 HTTP 资源检查。真实浏览器验证了「构造剩 46 秒切英文变 45 秒」「打开规则剩 31 秒」等计时细节——这些数字证明「看规则不暂停计时」真的成立。

**V2.1（白纸黑墨修订）** 验收：90 项测试、30 项本地 HTTP smoke，桌面 1280×720 加上 320×680 / 390×680 / 760×900 视口。

**V3（电影感动效层）** 验收：101 个 JS 文件、28 个浏览器模块、135 项测试 0 失败、48 项 HTTP smoke；桌面 15 枚、手机 8 枚粒子；约 2.9 秒后收尾层自动移除。

从 90 到 135 项测试的增长，与动效层的加入同步——每加一层表现，都补上相应的验证。

## 六、降级与可访问性

动效系统有两条降级路径：

1. **系统偏好优先**：`prefers-reduced-motion`（系统减少动态效果）优先于应用内开关。用户系统层面说了「别动」，应用就必须听。
2. **应用开关**：设置中可关闭动效，另有可暂停、拖动、对比原图的独立动态漫画示例。

需要强调的是：**关闭动效不会暂停对局**。动画是对事实的演出，关掉演出不影响演出背后发生的事。这一点和「看规则、看记录、切语言都不暂停呼吸」是同一条设计原则。

## 七、移动端与响应式

响应式不是「能挤进去」就行，而是针对触摸场景重新安排交互：

- 手机候选牌**纵向排列**，操作栏进入正常文档流，避免遮挡第三项候选——这是专门修过的问题。
- 触屏设备上复制按钮补齐了 `@media (hover:none)` 可见性规则。
- 独立教学的目标数字调整为 24 和 30，各配三条与高牌示例，适合触屏练习。
- 首屏图片有体积预算：手机约 69 KB、桌面约 180 KB；发布预算总量 4 MB、运行插画 2 MB、首屏单图 300 KB。

真实浏览器回归覆盖 390×844、320×680、360×740、430×850、1440×900 等视口，根路径与子路径都跑。

## 八、独立动态漫画示例

设置里还有一个独立于游戏的动态漫画示例：

- 12 秒时间轴，支持暂停、重播、拖动；
- 两档强度（轻柔 / 沉浸）与原图对比；
- 角色只做整体轻浮、轻旋转、视差，没有表情、骨骼或逐根头发的动画；
- `browser/motion-demo.js` 独立时间轴，**不读游戏、计时或存储状态**。

验收包括 66 个回归测试、35 个本地 HTTP 资源；Chromium 下拖到 3 秒显示 03.0，0 秒与 12 秒的变换只有浮点尾差（即循环无缝）；从首页入口进示例再返回开局，双方未开 AIR 仍为 24——证明示例完全不影响对局。

## 九、核心讲解：表现与对局解耦

把界面与动效部分收拢，核心是三个「不」：

1. **动画不触发结算**：Canvas 与场景动效只消费公开事件，动画完成不派发任何引擎动作。
2. **渲染不持有状态**：ui 只消费快照；教学与动态漫画示例各自持有独立视图状态，与正式对局隔离。
3. **演出不暂停事实**：关闭动效、看规则、切语言、切后台都不改变真实截止时间。

> 解耦带来的最大好处是：你可以任意改动视觉表现（V2 → V2.1 → V3），而不需要碰游戏核心，也不用担心演出改动会影响规则正确性。反过来，规则改动也不会让动画逻辑失真——动画只认公开事件，不认内部实现。

## 十、使用建议与推荐结论

**使用建议：**

1. **让界面说真话**：能用状态实时渲染的，就不要用预生成图片或示例数据替代。
2. **动画只消费事实**：把「演出」和「结算」彻底分开，能省掉大量状态同步的痛苦。
3. **降级要成体系**：系统偏好 > 应用开关，且关闭演出不能影响主流程。
4. **为触摸重排**：手机不是缩小版桌面，候选排列、点击区域、按钮可见性都要单独验。

**推荐结论：**

- 这套视觉与动效方案适合**重视氛围但同样重视正确性**的项目——游戏、教学工具、数据叙事、交互式文档都能借鉴。
- 它不适合「纯信息展示、动效可有可无」的场景，那里投入产出比不高。
- 最值得推荐的一点是「真实渲染」的坚持：它让界面成为状态的可信镜像，而不是一层可以掩盖问题的装饰。
