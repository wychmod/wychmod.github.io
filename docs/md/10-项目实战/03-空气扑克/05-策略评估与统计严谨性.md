## 一、为什么需要一套评估方法

改了 AI 的构牌权重，怎么知道它变强了？跑几局看胜率？远远不够——单局波动大、发牌有运气、双方持牌不对称，随便一组数字都能讲出相反的故事。

空气扑克给出的答案是把评估当成一个正式工程：`npm run evaluate:strategy` 用固定种子驱动真实引擎跑完整局，支持旧策略、新策略、被动、激进等基准，并对同一发牌交换双方持牌以抵消座位优势。

推进顺序也是刻意定的：**整局基准 → 多轮选牌 → 下注判断 → 发牌决策**。先有能复现的整局基准，才谈得上拆分归因；证据不足时，宁可保留现行发牌规则。

## 二、固定种子整局基准

评估的核心机制是「同一副牌，不同策略，反复对比」。

| 机制 | 说明 |
|---|---|
| 固定种子 | 每个种子确定一发牌序列；发牌随机源与策略随机源**分离**，避免互相干扰 |
| 整局复用真实引擎 | 不是简化模型，而是把 `createGame` 跑到实际耐息终局 |
| 交换持牌 | 同一发牌下交换双方数字各跑一次，抵消先后手与持牌差异 |
| 独立样本 | 开发集（种子 1–100）调参，独立集（10001–10100）验证 |
| 账户核对 | 每次动作核对账户，完成记录经 `isCompletedRecord` 验证 |
| 源码指纹 | 报告保留核心源码 SHA-256，保证结果可追溯 |

以难度验证为例，每组配置为：三档难度 × 两个玩家基准 × 100 种子 × 两次换边 = **1,200 局**。两份独立验证合计约 2,000 局。

节奏也可配置：正常节奏为选数字 1 秒、构造 12 秒、双方下注 600 ms；`--slow` 用 55 秒构造节奏验证守恒。

## 三、分阶段消融：收益到底来自哪里

这是整套评估最精彩的部分。作者不只看「新版 vs 旧版」，而是把改动拆开，逐项归因。

| 策略 / 对手 | 胜/平/负 | 得分率 | 近似 95% 区间 |
|---|---|---|---|
| 旧版 / 旧版 | 108/3/89 | 54.75% | 50.47%–59.03% |
| 仅改选牌 / 旧版 | 104/5/91 | 53.25% | 48.15%–58.35% |
| 仅改下注 / 旧版 | 151/1/48 | 75.75% | 70.66%–80.84% |
| 完整新版 / 旧版 | 149/2/49 | 75.00% | 69.74%–80.26% |
| 完整新版 / 被动 | 169/1/30 | 84.75% | 80.24%–89.26% |
| 完整新版 / 激进 | 166/0/34 | 83.00% | 78.33%–87.67% |
| 完整新版 / 完整新版 | 96/1/103 | 48.25% | 45.62%–50.88% |

**结论出人意料但很重要**：新版的收益**主要来自下注**，而不是选牌前瞻。「仅改选牌」的得分率（53.25%）甚至低于旧版基线（54.75%），而「仅改下注」一项就把得分率推到 75.75%，完整新版（75.00%）并未超过它。

那为什么还保留选牌前瞻？因为有一个具体回归案例证明它能避免耗尽后续解（见 04 篇）。**在统计上没有证实胜率提升、但有明确反例支撑的功能，作者选择保留并如实说明**。这种「数据说话 + 案例兜底」的组合，比「数据好就上、数据不好就砍」更成熟。

## 四、独立验证集与参数冻结

防止过拟合的两个纪律：**用开发集调参、用独立集验证、验证集不再回头调参**。

具体过程：在开发种子 1–40 上，第一版用 `0.35` 的前瞻权重，结果「仅改选牌」得分率只有 44.375%。据此判断前瞻牺牲过大，下调权重。在种子 41–80 复核后**冻结参数**。独立样本 10001–11000 只用于验证，不再参与调参。

> 这是机器学习评估里的标准做法，但在游戏 AI 项目中常被省略。项目把它明确写进文档，并附上参数演进过程，让读者能判断「这个数字是不是被调出来的」。

## 五、置信区间：为什么按交换持牌聚类

这是统计处理上最容易被做错的一步。

得分率定义为 `(胜 + 0.5 × 平) / 局数`。近似 95% 区间**不是**把 200 局当 200 个独立样本算，而是**把同一发牌下的「交换持牌两局」聚成一个样本**再计算。

原因很直白：交换持牌的两局共享同一副牌，它们不是独立的。如果当成独立样本，区间会被人为压窄，看起来「显著」的结论可能只是噪声。项目在每张结果表上都附上近似区间，让「差异是否可信」一目了然——这也是为什么困难档相对中等的 +1.5 个百分点被诚实地标注为「区间覆盖零」。

## 六、发牌公平性怎么验

如果发牌本身偏袒某一方，策略评估就失去了基准。项目对发牌做了两项验证：

- **总和差**：对种子 10001–11000 的 1,000 次发牌，966 次双方数字总和差 ≤ 1，最大差为 5。
- **开局牌力**：开局最强完整牌型玩家更强 463 次、对手更强 460 次、相同 77 次。

结论是保留现行发牌规则（十组证明成手 → 最小化双方数字总和差 → 随机分配双方），因为证据不足不支持改动。

作者同时给出限制说明：数字总和相近**不是**牌力、灾厄或胜率公平的证明；新版自我对战区间含 50%，但旧版自我对战有样本局限，不能据此宣布「完全公平」。

## 七、诚实的边界：没证实就不宣布

整套评估反复出现的关键词是「不确定」。项目明确列出多种不下结论的情形：

- 选牌前瞻的胜率提升**未被证实**（区间重叠，完整新版未超过仅改下注）。
- 困难与中等的差异**有限**，需要真人校准，不能预测玩家胜率。
- 模型概率不是实际胜率；前瞻不保证未来可解。
- 性能数据均为**本机测量**，不代表浏览器或手机。
- 账目收益指标 `meanAirGain` 是进入耐息前的未开余额变化，**不是最终剩余供气**。

> 这些「不宣布」不是软弱，而是可信度的来源。一个把所有数字都包装成「胜利」的项目，反而让人不敢用它的结论。

## 八、核心讲解：把「感觉更强」变成证据

把整套方法收拢成一套可复用的流程：

1. **可复现**：固定种子 + 随机流分离 + 真实引擎整局模拟。
2. **可归因**：分阶段消融，拆开看每处改动各自的贡献。
3. **可防过拟合**：开发集调参、独立集验证、参数冻结。
4. **可判可信度**：按交换持牌聚类的置信区间，而非裸胜率。
5. **可追溯**：报告保留源码 SHA-256 与完整参数。
6. **诚实的边界**：区分「已证实」「有案例支撑但未证实」「样本不足」。

> 这套流程的价值远超游戏 AI。任何需要做 A/B 对比、策略调优、算法迭代的团队，都能直接套用这六步——尤其第 4 和第 6 步，是多数团队最容易省略、也最容易翻车的地方。

## 九、使用建议与推荐结论

**使用建议：**

1. 评估任何改动前，先搭好**可复现的整局基准**，否则后面所有分析都是空中楼阁。
2. 一定要做**消融实验**——本项目正是靠它才发现「收益主要来自下注而非选牌」这个反直觉结论。
3. 报数字时同时给**置信区间和样本聚类方式**；样本不独立时不要假装独立。
4. 对「没证实但有价值」的功能，写明保留理由（如具体回归案例），不要硬凑数据。

**推荐结论：**

- 本篇是全系列最值得跨学科借鉴的一篇：它把「如何科学地评估一个改动」做成了可执行的工程流程。
- 适合推荐给做推荐算法、搜索排序、游戏 AI、A/B 测试的团队作为方法论参考。
- 它不提供「如何让 AI 必胜」的秘籍——恰恰相反，它示范的是如何克制地、诚实地谈论「更强」。这种克制在当下的技术传播里尤其稀缺。
