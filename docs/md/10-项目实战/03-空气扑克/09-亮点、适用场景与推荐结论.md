## 一、十条横切亮点

把前十篇内容压成十条最值得记住的亮点：

| # | 亮点 | 一句话 |
|---|---|---|
| 1 | 一份空气两种用途 | AIR 既是筹码又是呼吸，让眼前牌力与长期生存相互牵制 |
| 2 | 零运行时依赖 | 原生 Web 平台、无编译、无后端、无账号，打开 URL 就能玩 |
| 3 | 考据可信度分层 | 明确区分原作事实 / 二手整理 / 数字版约定，不把自创说成原作 |
| 4 | 核心与平台硬隔离 | `game/` 不碰 DOM/网络/存储/计时器，可在纯 Node 导入测试 |
| 5 | 隐私做在数据出口 | `getState()` 主动隐藏对手信息，界面没有能力「猜牌」 |
| 6 | 动作带身份防重 | sessionId / attemptId / turnId 让旧回调、重复扣款无从发生 |
| 7 | 时间基于绝对时长 | 后台恢复与分步推进结果一致，切语言/看规则不续时 |
| 8 | 50 罐守恒账本 | 逐笔可重放、可导出 JSON，收款与净赚显式区分 |
| 9 | 不作弊的 AI + 严谨评估 | 信息隔离、固定种子基准、消融实验、置信区间、诚实边界 |
| 10 | 事实驱动的动效与降级 | 动画只消费公开事件、不触发结算；尊重系统减少动态偏好 |

每一条都在前面的专题篇里有完整展开，这里只做索引。

## 四、明确不做什么

诚实地列出边界，才能建立正确预期。项目自己明确声明不做或不声称：

| 边界 | 说明 |
|---|---|
| 不是多人联机 | 单人浏览器游戏，对手是本地 AI，无后端对战 |
| 不是原作 1:1 | 合并上下层、自动换罐、固定宽限等均为数字版改编 |
| 无必胜 AI / 最高胜率 | 三档 AI 只作难度区分，文档拒绝宣称最强 |
| 不模拟真实生理 | 供气是确定性计时，不是个人生理模型 |
| 不做存档读档 | 只保存最近一局完成局，不恢复未完成对局 |
| 不做防篡改 | 记录可导出但无签名认证 |
| 不做跨局用户画像 | 困难档只在本局内适应，不积累对玩家的长期画像 |

这些不是缺陷，而是**清晰的产品取舍**。把它们说在前面，反而让项目更可信。

## 五、谁最值得读这个系列

综合来看，这个系列对四类人的价值最高：

1. **想提升架构能力的初中级开发者**：这是一个能一口气读完、又能看到「约束如何落地」的完整样本，比空谈设计原则具体得多。
2. **做博弈 / 策略 / 模拟的开发者**：从规则设计、AI 决策到策略评估，是一条少见的完整链路。
3. **重视可复现与可信度的研究者**：05 篇的评估方法论与 06 篇的账本设计，都有超出游戏领域的普适价值。
4. **需要「把事情讲清楚」的人**：整个项目本身就是一份写作范本——从 README 到 doc 文档，处处体现「说清依据、说清边界、说清未验证部分」。

本知识库的「项目实战」分类下已有多个系列，本篇给出定位对比：

| 系列 | 领域 | 主打 | 与空气扑克的关系 |

简单说：前三个系列偏「后端中间件与工程」，空气扑克偏「前端交互 + 算法评估 + 诚信工程」，正好补齐版图。

## 七、核心讲解：小项目的价值密度

如果只能用一句话概括这个系列的意义：**它证明了「小」不等于「浅」。**

一个零依赖、约 9,100 行、没有后端的浏览器游戏，却同时具备：

- 严谨的规则考据与改编边界；
- 硬隔离的分层架构与自动检查；
- 确定性状态机与绝对时长时钟；
- 不作弊的三档 AI 与科学的策略评估；
- 可审计、可重放的账本；
- 事实驱动、可降级的动效系统；
- 完整的质量门禁与诚实的传播设计。

每一项单拿出来都不新鲜，但**同时做对、还配上 202 个测试和完整文档**，非常罕见。这正是它值得被当教材、被推荐的原因。

> 对读者最有价值的，往往不是「学到了某个 API」，而是「看到一种把事情做扎实的态度如何落到每一行设计里」。空气扑克提供的正是这种观察机会。

## 八、总体推荐结论

**推荐指数：推荐（尤其推荐给前端、算法与工程教学场景）。**

**推荐理由（三条）：**

1. **完整性**：从玩法、规则、架构、AI、账本、界面到质量与传播，一条链路全覆盖，是难得的全景样本。
2. **可信度**：所有结论都有依据——考据分层、评估区间、账目守恒、性能条件、故障注入，处处可复核。
3. **可迁移**：它提炼的模式（边界即正确性、记录只记事实、动画只消费事件、诚实报数据）跨领域适用。

**阅读建议（一句话路径）**：时间有限读 00 + 09；做工程读 02 + 03 + 06；做 AI 读 04 + 05；做界面读 07；关心交付读 08。

**最后提醒**：把它当「如何把一件事做扎实」的工程样本，而不是「如何赢一局扑克」的攻略——后者只是它的外壳，前者才是它的内核。
