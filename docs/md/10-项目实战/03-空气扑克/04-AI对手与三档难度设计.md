## 一、信息隔离：AI 被禁止看到什么

单机游戏做 AI 最容易偷的懒，就是让 AI「看一眼玩家的牌」。空气扑克把这条路直接封死。

**对手在玩家选择之前，就锁定自己的数字与成手。** 它的决策白名单是：

| 可用信息 | 不可用信息 |
|---|---|
| 自己的五张私有数字 | 玩家未公开的数字 |
| 自己锁定的成手或失败状态 | 玩家的实际成手与候选 |
| 本轮公开数字、剩余数量 | 玩家的构牌草稿 |
| 公共弃牌 | 来源证明 |
| 公开的账户余额与下注历史 | 任何未来信息 |

策略只接收白名单信息的**副本**，返回的成手也复制一份——连「通过共享引用偷改数据」的可能都堵住了。这些注入入口（`choosePlay` / `chooseBet`）不增加界面的私有数据。

**无解时的处理**：若对手剩余数字全部无解，它仍从自己的未用数字中选一张，记为失败尝试，**不生成替代数字**。这保证对手和玩家遵守同一套规则，不会「悄悄换一手好牌」。

## 二、构牌决策：有限前瞻而非全知

对手构牌时综合三件事：当前牌力、移除成手后剩余数字的可解性、剩余数字牌力。

| 评分要素 | 权重 / 处理 |
|---|---|
| 当前成手牌力 | 基础项 |
| 消耗成手后剩余数字牌力总和 | `0.04 ×` 剩余牌力 |
| 每个无解的剩余数字 | 计 `−2.5` |
| 同分候选 | 随机选择 |
| 单次决策局部缓存 | 最多评估 15 个成手 |

这叫**有限前瞻**：它会考虑「我这手牌用掉实体牌后，后面的数字还能不能成手」，但不保证未来一定可解。项目文档明确写道：模型评分不是实际胜率，前瞻不保证对手弃牌后仍有解。

为了说明前瞻为什么有价值，项目保留了一个具体回归案例：剩 13 张实体牌、数字 37 和 25 时，旧版先组出两对 A+10，导致 37 无解；新版先组两对 10+2，保留了 25 的合法成手。**这类具体案例是保留前瞻的依据**——即便统计上没证实它能提高胜率，它能避免明确的死局。

## 三、下注决策：公开信息的加权模型

下注判断基于一个「有限候选模型」：

- 从公开数字构造至多 **12 个强候选**，按牌力加权；玩家本轮加注次数会增加强牌权重。
- 比较三类动作：跟注、加注到下注增量的 1/3、加到半上限、加到上限；同值随机。
- 加注时**假设会被跟注**，不虚构「迫使对手弃牌」的收益——这是对模型不确定性的诚实处理。
- 合法性判断与实际扣款仍由 `betting` / `engine` 决定，AI 只表达偏好。
- 困难档单次规划最多 256 次候选缓存未命中、深化两次己方出牌、四个根分支、三个后继代表；不把「未探索」当作「无解」。

> 关键点：模型概率是**假设分布**，不是真实胜率。项目在文档里反复强调这一点，避免读者把 AI 的内部评分误读成「它算准了你有多大的牌」。

## 四、三档难度：靠什么区分强弱

三档共用同一套牌力、费用与灾厄判断，难度差异来自三处：**规划深度、风险判断、公开信息利用**。

| 难度 | 固定映射 | 规划特点 | 固定目标 |
|---|---|---|---|
| 新手 | beginner | 优先处理当前回合，减少后续构牌规划与复杂下注尺寸；所有成手仍须有效，不靠故意无效牌或超时制造简单 | 标准对局 |
| 中等（默认） | comeback | 保留有限前瞻与牌力、费用、灾厄判断；弱牌高成本能止损，强牌有合理投入机会 | 曾落后后夺冠 |
| 困难 | perfect | 更充分权衡消耗后剩余数字可解性；根据本局玩家已公开行动调整判断 | 赢下每个已结算回合并夺冠 |

几个产品层面的约定：

- 默认中等；选择跨刷新保存，非法或旧偏好安全回退到中等。
- 三档是**固定映射**，取代了早期的独立契约选择；旧 `air-poker-contract` 偏好不再读写。
- 每档自带固定目标：难度与目标一一绑定，「困难」意味着要达成全胜压制。
- 难度契约与难度独立，不改变发牌、时限、规则或信息权限——**难度只改 AI 的脑子，不改游戏规则**。

## 五、困难档的本局自适应

困难档是唯一会「学习」玩家的一档，但学习范围被严格限定。

引擎维护最近 **64 个**已接受下注的白名单观察：在动作接受前采集 session / round / attempt / turn 以及应跟额、加注上限；接受后加入实付金额与超时标识。

- 非法、重复、过期动作不追加；`reset()` 清空。
- 只向 `chooseBet` 传副本，不放入 `getState()`，不从记录器反向读取。
- 统计分别按机会计数；超时不作为主动偏好；少量样本按先验平滑。
- 困难档**只在本局内适应，不保存跨局画像**。
- 公开行为不足时回退基础模型；适应不能简化为「玩家加注就反加」。

这套设计的分寸感值得注意：它让困难档「看得见你在这一局里的习惯」，但既不读取你的隐藏信息，也不跨局积累对你这个人的画像——在博弈感和隐私边界之间取得了平衡。

## 六、难度效果的实测数据

三档强弱不是靠感觉宣布的，而是用固定种子机器人基准跑出来的（详见 05 篇）。

独立验证集（种子 10001–10100）结果，得分率 = 胜 + 0.5×平：

| 玩家基准 | 对手：新手 | 对手：中等 | 对手：困难 |
|---|---|---|---|
| legacy（旧版策略） | 70.50% | 76.75% | 78.25% |
| current（当前策略） | 44.25% | 51.75% | 53.75% |

两组点估计都按 **新手 ≤ 中等 ≤ 困难** 排列。困难相对中等的配对变化：legacy 为 +1.50 个百分点（95% 区间 −0.68…+3.68，覆盖零），current 为 +2.00 个百分点（+0.07…+3.93，刚高于零）。

**作者的诚实结论**：差异有限，需要真人校准，不能据此预测玩家胜率。这正是 05 篇要展开的统计严谨性。

性能方面，困难档单次规划最慢约 400 ms（开发机引擎测量，不代表浏览器或手机）；浏览器实测选牌平均约 60 ms、P95 约 73 ms，下注平均约 1.5 ms——这些同样是本机数据，文档明确标注不代表真机。

## 七、核心讲解：不作弊的 AI 才有博弈感

把三档设计合起来看，贯穿始终的原则是：**难度来自决策质量，不来自信息特权或数值加成。**

- 信息上，AI 和你看到的一样多（都只有自己的私牌 + 公开信息）。
- 规则上，AI 和你受同样约束（无解时也得记失败尝试，不换牌）。
- 差异上，只是 AI 想得更深（前瞻、候选模型、本局自适应）。

> 这带来一个重要的体验结果：你会觉得是在和一个「更会算的对手」较量，而不是和一个「偷看牌的裁判」较量。前者让人愿意再来一局，后者只会让人觉得被耍。

对工程而言，这套设计还有个副作用好处：因为 AI 只吃白名单信息 + 可注入随机源，整局博弈可以被固定种子复现，从而支持科学的策略评估——这是「不作弊」换来的额外馈赠。

## 八、使用建议与推荐结论

**使用建议：**

1. **做游戏 AI 时**，先写下「AI 禁止看到什么」清单，比先写决策逻辑更重要。
2. **难度分级**优先调规划深度和可用信息，最后才考虑数值加成；数值加成最容易被玩家识破。
3. **报告 AI 强度**时，用固定种子基准 + 独立验证集 + 置信区间，不要只报单组胜率。

**推荐结论：**

- 这套「受限信息 + 有限前瞻 + 本局自适应 + 固定目标」的组合，是单机博弈 AI 的优质范本，尤其适合棋牌、策略、模拟类项目。
- 它不适合「AI 需要有全局信息的对话/推荐系统」——那些场景本就没有对抗性，信息隔离反而会削弱效果。
- 最值得借鉴的一句话是：**把模型概率说成假设而非胜率**。这种诚实不仅避免误导用户，也逼着开发者把评估做扎实（见 05 篇）。

## 附录：期望收益公式与三档参数

> 对应源码：`game/ai-betting.js` 的 `estimateShowdown()`、`betValue()`、`chooseDifficultyBet()`；`game/difficulty.js`。

### 第一步：估对手的牌

```js
const candidates = makeCandidates(opponentTarget, discard, 12);
const weight = Math.exp(
  (handStrength(candidate.rank) - best) * (2 + Math.min(4, pressure) * pressureScale)
);
```

- 只取对手目标下**最强的 12 个候选**，不是按概率抽样；
- `handStrength` 把牌型和踢脚压成一个连续分，牌型差一级就压过任何踢脚差；
- `pressure` 是玩家本局加注次数；加注越多，模型越「相信」对手有强牌；
- 输出 `win / tie / lose / overlapLoss` 四个比例，其中 `overlapLoss` 是「我输且实体牌重叠」的加权概率。

### 第二步：算每个动作的期望

```js
const cost = options.toCall + raise;
const pot = options.potAfterCall + 2 * raise;
const committed = pot / 2;
const burned = Math.min(Math.max(0, options.reserve - cost), committed);
return model.win * pot + model.tie * committed - cost - model.overlapLoss * burned;
```

| 项 | 含义 |
|---|---|
| `cost` | 这次要掏多少：应跟 + 加注增量 |
| `pot` | 假设对手会跟你的加注，底池变成多大 |
| `committed` | 摊牌时你这边的总投入，用于平局退回和烧毁上限 |
| `burned` | 如果输了且重叠，最多烧掉多少 |
| 结果 | 赢时拿整池 + 平时拿回自己那份 − 这次掏的钱 − 重叠输时烧掉的期望 |

基准是「现在弃牌、之前投的都不要了」，所以它是**决策价值**，不是绝对盈亏；沉没投入不重复扣。

### 第三步：难度把它变成评分

```js
score = betValue(...) - riskWeight * cost² / max(1, reserve);
```

风险项不是真扣 AIR，而是让 AI 在期望接近时偏向小注；二次方意味着大注惩罚更重。

| 参数 | 新手 | 中等 | 困难 |
|---|---|---|---|
| `candidateLimit` | 3 | 12 | 12 |
| `planningDepth` | 0 | 1 | 2 |
| `beamWidth` | 0 | 0 | 4 |
| `riskWeight` | 0.35 | 0.12 | 0.16 |
| `betTolerance` | 0.2 | 0.1 | 0.05 |
| 加注尺寸 | 只有 1 | 1 / 半池 / 满池 | 1 / 1/4 / 1/2 / 3/4 / 满池 |
| 本局自适应 | 否 | 否 | 是 |

困难档的风险权重比中等高，不等于更保守；它靠更多尺寸、更小容差、两层前瞻和适应能力取胜。

### 两个真实例子

**例 A：没有重叠，加注更好。**
手牌 `2♠ 4♥ 4♦ 4♣ 4♠`（目标 18），对手目标 18；底池 3，应跟 1，最大加注 2，储备 3。模型：赢 63.4%，输 0%，重叠 0%。

| 动作 | 期望 AIR |
|---|---|
| 跟注 | 2.267 |
| 加 1 | 2.901 |
| 加 2 | 3.534 |

| 档位 | 跟注 | 加 1 | 加 2 | 选择 |
|---|---|---|---|---|
| 新手 | 2.151 | 2.434 | 不允许 | 加 1 |
| 中等 | 2.227 | 2.741 | 3.174 | 全押（等于加 2） |
| 困难 | 2.214 | 2.687 | 3.054 | 全押 |

新手不是不想加 2，是它的尺寸表里只有 1；中等和困难的风险罚分更低，所以敢加到上限。加注刚好等于全押成本时，动作会被记成 `all-in`，付款和加注完全一样。

**例 B：必然重叠，加注反而降低期望。**
手牌 `2♠ 5♥ 5♦ 5♣ 5♠`（目标 22），对手目标 21；底池 6，应跟 2，最大加注 4，储备 22。模型：赢 60.6%，输 39.4%，**重叠也是 39.4%**，每次输都重叠。

| 动作 | 期望 AIR |
|---|---|
| 跟注 | 1.277 |
| 加 1 | 1.096 |
| 加 2 | 0.915 |
| 加 4 | 0.553 |

越加越差：`committed` 随加注变大，烧毁上限跟着变大；每次输都要烧，多赢的那点底池补不回来。这一手三档都选择跟注。

三个必须记住的边界：模型是启发式，不是真实胜率；加注时假设对手一定跟注，所以不含「对手弃牌」的收益；只取 12 个候选，不枚举对手所有实体方案。
